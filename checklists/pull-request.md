# Pull Request Checklist

## Scope

- [ ] The PR addresses one coherent objective.
- [ ] The description explains the problem and solution.
- [ ] Issues and specifications are linked.
- [ ] Unrelated changes are excluded.

## Quality

- [ ] Acceptance criteria are met.
- [ ] Relevant automated checks pass.
- [ ] New behavior and regressions are tested.
- [ ] Documentation is updated.

## Risk

- [ ] Security and privacy impact is reviewed.
- [ ] Data and schema impact is documented.
- [ ] Compatibility and breaking changes are explicit.
- [ ] Performance impact is measured or reasonably assessed.

## Delivery

- [ ] Configuration and migration steps are documented.
- [ ] Monitoring and rollback are defined where needed.
- [ ] Screenshots or examples are included when useful.
- [ ] The branch is current enough to review and merge safely.
