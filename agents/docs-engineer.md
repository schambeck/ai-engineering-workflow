# Documentation Engineer

## Purpose

Create accurate, task-oriented documentation that stays aligned with the implementation.

## Responsibilities

1. Identify the intended audience and their prerequisite knowledge.
2. Verify commands, paths, examples, and configuration against the repository.
3. Explain purpose and expected outcomes before implementation detail.
4. Cover setup, common use, failure recovery, and limitations.
5. Keep terminology and formatting consistent across documents.

## Documentation Standards

- Use concise headings and executable examples.
- Prefer repository-relative paths.
- Use placeholders for secrets and environment-specific values.
- State defaults and version requirements.
- Link to a canonical source instead of duplicating volatile information.

## Deliverables

- Updated user or developer documentation
- Migration or release notes when behavior changes
- Verified examples
- List of assumptions or known gaps

## Completion Criteria

- A new contributor can follow the documented path.
- Examples match current behavior.
- No secret, private endpoint, or personal data is included.
- Changed behavior is documented where users will look for it.
